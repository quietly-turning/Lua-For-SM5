Setting Up a "Mod" Chart

StepMania simfiles can be scripted to enhance gameplay using Lua and the SM5 API. This chapter will briefly demonstrate how to prepare a simfile for such scripting.

This chapter is a work-in-progress!

Loading Lua Script Through FGCHANGES

In StepMania, stepcharts can load Lua code as a "foreground animation" through the FGCHANGES field in a stepchart's .ssc file. StepMania's built-in stepchart editor does not have any way to configure the FGCHANGES field directly, so you'll need to open your stepchart's .ssc file in a text editor and add the line yourself.

The FGCHANGES field in your .ssc file accepts several arguments delimited by equals signs. The first two are the most important:

  • the beat in Gameplay at which you want the Lua file to be activated
  • a path to the Lua file where you will be writing your code

So, for example, if you named your script default.lua and wanted it to trigger at beat 4, you would need to change your .ssc file to include: 

#FGCHANGES: 4.000=./default.lua=1.000=0=0=1=====;

The other arguments (the 1.000 and subsequent 0s and 1s) are various flags that are basically vestiges from SM3.9 that are necessary to include but will have no impact on your Lua. For FGCHANGES, you can just copy/paste them into your .sm file for each FGCHANGE.

FGCHANGES must be constantly animating

Any Lua-based actors loaded as FGCHANGES will be marked as done/complete by the engine as soon as no actors are actively tweening in some way.

A common strategy is to ensure that this doesn't occur prematurely is to add a dummy keep-alive Actor that does nothing but sleep for as long as you want the overall Lua file to persist for. That might look like: 


-- a Lua file can only return one Actor
-- the common strategy is to return one ActorFrame that contains many sub-Actors
return Def.ActorFrame{
   -- keep-alive Actor
   -- this will allow the file and all its actors to persist for 999 seconds
   -- or, until the end of the stepchart, whichever comes first
   Def.Actor{ OnCommand=function(self) self:sleep(999) end },

   -- the Sprite Actor
   Def.Sprite{
      Texture="awesome.png",
      OnCommand=function(self)
         self:Center():FullScreen():sleep(3):diffusealpha(0)
      end
   }
}

In the example above, the the Sprite has a sleep(3) tween, so it would appear on the screen for 3 seconds at beat 4 (specified by the .sm file) and then have an alpha of 0 applied, causing it to be effectively invisible.

Common Gotchas

If you are testing this in SM5's editor, you'll need to ensure that you have Show Background Changes enabled, otherwise neither BGCHANGES nor FGCHANGES will appear.

SM5's Lua error reporting interface is invaluable when scripting things like this. You can toggle it on/off by holding F3 and tapping F6 then tapping 8

Finally, if there are no Lua errors, and you still can't get anything to appear, you may need to reload your stepchart.
